### graphify (코드 지도)

- **코드 그래프**는 LLM을 쓰지 않는 tree-sitter 분석이다. 위치는 프론트 `C:/LOAKraken/wt/graph-web/graphify-out/`, 백엔드 `C:/LOAKraken/wt/graph-api/graphify-out/`.
  - 파일: `graph.json`, `graph.html`(브라우저로 열어 보는 지도), `GRAPH_REPORT.md`(핵심 개념·의외의 연결 요약)
  - QA 정기 점검이 6시간마다 develop 최신으로 다시 만든다.
- **언제 쓰나**: 처음 손대는 영역의 구조 파악, 영향 범위 찾기('이걸 바꾸면 어디가 영향받나'), 전수 확인(회귀 점검표의 '다른 화면에도 있는지')을 할 때 쓴다. 원본 파일을 통째로 다시 읽기 전에 그래프로 좁히면 토큰이 준다.
- **명령**(CLI, 경로는 `C:/Users/qkrwl/AppData/Roaming/Python/Python312/Scripts/graphify.exe`):
  - `explain "<함수·컴포넌트 이름>" --graph <graph.json 경로>`
  - `path "A" "B" --graph <경로>`
- **팀별**:
  - 프론트·성장 도구·디자인 시스템: graph-web
  - 백엔드·계산 검증·PM-백엔드: graph-api
  - 보안팀: 둘 다
  - QA: 영향 범위 확인
- **주의**: 그래프는 최대 6시간 늦을 수 있다. 판단은 소스로 확인한다. 그래프 작업 트리에서 커밋하거나 수정하지 않는다.
- `/graphify` 스킬도 등록됐다(10-12 사용자 설치). 코드 질문은 graphify-out이 있으면 먼저 그래프로 묻는다. 문서·이미지까지 그래프로 만들 때(예: 볼트 레퍼런스 폴더) `/graphify <폴더>`를 쓴다. 이때는 LLM 추출이 들어가 토큰을 쓰니 필요할 때만 쓴다.

### 옵시디언 세컨 브레인 (모든 팀, 2026-10-12 사용자 지시)

볼트 연결을 고쳤다. 설정 파일은 `~/.config/obsidian-second-brain/.env`이고 `OBSIDIAN_VAULT_PATH`가 이 볼트를 가리킨다. 볼트 작업은 아래 순서로 한다.

- **찾기**: 파일을 열기 전에 `obsidian_search`로 찾는다(MCP 도구 `mcp__plugin_obsidian-second-brain_vault__*`). 관련 문서를 따라갈 때는 `obsidian_backlinks`를 쓴다.
- **쓰기**: 새 문서는 `obsidian_save_note`, 고칠 때는 `obsidian_update_note`를 쓴다. 저장한 뒤 `obsidian_validate_note`로 frontmatter와 링크를 확인한다.
  - 전달함 한 줄 추가는 지금처럼 파일 끝에 덧붙여도 된다.
- **기록**: 하루 작업 로그는 `obsidian-second-brain:obsidian-log`·`obsidian-daily` 스킬로 `Logs/YYYY-MM-DD/<팀>.md`에 쓴다(기존 팀별 로그 규칙 그대로). 결정은 `obsidian-decide`, 빠른 메모는 `obsidian-capture`로 남긴다.
- **조사**: 레퍼런스·계산 검증은 `obsidian-second-brain:research`·`research-deep`로 조사 결과를 볼트에 바로 저장한다(외부 API 키가 필요한 모드는 키가 없으면 무료 모드로).
- **정리**: PM 총괄은 하루 한 번 `obsidian_vault_health`로 고아 문서와 frontmatter 누락을 확인한다.
