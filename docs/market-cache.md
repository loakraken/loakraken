# 거래소 검색 옵션과 단기 캐시

## 검색 옵션 API

`GET /api/v1/markets/options`는 공식 `GET /markets/options`에서 읽은 카테고리·하위 카테고리·등급·티어·직업을 제공한다. 성공은 `200 MARKET_OPTIONS_SUCCESS`다.

```json
{
  "code": "MARKET_OPTIONS_SUCCESS",
  "message": "거래소 검색 옵션 조회에 성공했습니다.",
  "data": {
    "observedAt": "2026-10-04T00:00:00Z",
    "categories": [{"code": 50000, "codeName": "예시 재료", "subs": []}],
    "itemGrades": ["일반"],
    "itemTiers": [4],
    "classes": ["바드"]
  }
}
```

위 값은 응답 형태를 보여주는 합성 예시이며 실제 최신 선택 목록이 아니다. 카테고리의 `code/codeName/subs`와 하위 항목의 `code/codeName`을 반환한다. 하위 목록이 없으면 `subs=null`, 제공된 빈 목록이면 `subs=[]`다. 최상위 네 목록은 필수이며 null·누락·null 원소·잘못된 항목은 외부 응답 오류로 처리한다. 제공된 빈 최상위 목록은 그대로 반환한다.

검색 화면은 이 API의 선택 목록을 사용할 수 있다. 가격 검색이 옵션 API를 자동 호출하거나 이 목록으로 검색 조건을 추가 검증하지는 않는다. 기존 형식 검증은 유지하며, 공식 서버가 거절하는 조건은 여전히 502다. 새 카테고리나 등급은 옵션 캐시 갱신 이후 보일 수 있다.

## 캐시 정책

| 대상 | 기본 TTL | 설정 | 공개 환경 변수 |
|---|---|---|---|
| 현재 판매·최근 거래 한 페이지 | 30초 | market.cache.prices-ttl | MARKET_PRICES_CACHE_TTL |
| 검색 옵션 전체 | 10분 | market.cache.options-ttl | MARKET_OPTIONS_CACHE_TTL |

두 TTL은 양수여야 한다. 기본값을 쓰면 환경 변수 추가가 필요 없다. TTL은 API 호출량과 신선도를 위한 서비스 설정이며 공식적으로 허용된 보관 기간을 확인했다는 뜻이 아니다. 보관·재제공 범위에 관한 기존 [검증 기록](source-verification.md)은 그대로 적용한다.

Valkey 키는 가격 `market:v1:prices:{SHA-256}`, 옵션 `market:v1:options`다. 가격 해시는 출처와 적용한 **모든** 검색 조건(categoryCode, characterClass, itemTier, itemGrade, itemName, pageNo, sort, sortCondition)의 JSON으로 생성한다. 현재 판매와 최근 거래, 페이지와 정렬이 서로 다른 응답을 재사용하지 않게 한다. 앞뒤 공백 제거·NFC와 기본값 적용은 기존 공개 요청 경계에서 수행한다. 해시는 키 길이를 고정하는 장치이며 캐시 내용 암호화를 뜻하지 않는다.

캐시 적중 시 `observedAt`은 최초 수집 완료 시각을 유지한다. 적중만으로 TTL을 연장하지 않는다. Valkey 만료 외에도 수집 시각이 현재보다 미래이거나 설정 TTL 이상 오래되면 재사용하지 않는다. 공개 응답은 캐시를 거쳤다고 실시간 가격으로 표시하지 않는다.

가격 문맥 불일치, 필수 데이터 누락·잘못된 수치 또는 손상된 JSON은 삭제 후 미적중으로 처리한다. 옵션의 null/빈 하위 목록은 캐시에서도 보존한다. 정상적인 빈 가격 결과나 빈 옵션 목록은 캐시할 수 있다. 외부 오류 응답은 저장하지 않는다.

이 기능은 장기 가격 이력이나 PostgreSQL 스냅샷을 만들지 않는다. API 키·공식 원문 오류 본문도 저장하지 않는다. Valkey 인프라의 영속화·백업 정책을 새로 설정한 것은 아니므로 TTL만으로 모든 저장 매체의 삭제를 보장한다고 해석하지 않는다.

## 동시 요청과 장애

같은 가격 출처·검색 조건의 동시 미적중 요청은 JVM 내에서 한 번만 수집한다. 옵션도 별도의 동일 요청 병합을 사용한다. 선행 수집자가 캐시 저장까지 성공해야 참여 요청들이 성공 응답을 받는다. 실패하면 실패를 공유하고 진행 중 요청 기록을 정리하므로 다음 요청은 다시 시도할 수 있다. 가격과 옵션, 서로 다른 검색 조건을 하나의 전역 잠금으로 묶지 않는다.

캐시 읽기·쓰기·손상 데이터 삭제가 실패하면 `503 MARKET_CACHE_UNAVAILABLE`을 반환한다. 읽기 장애를 미적중으로 바꿔 외부 호출을 늘리지 않으며 오래된 데이터를 대신 반환하지 않는다. 캐시 저장 실패는 외부 조회 성공 후에도 503이다.

캐시를 사용해도 캐릭터·가격·옵션의 실제 외부 요청은 동일한 90회/분·동시 4개 제한기를 통과한다. 외부 429 이후의 대기도 공유한다. 캐시 적중은 외부 요청 예산을 사용하지 않는다. 이 제한기와 요청 병합은 단일 인스턴스 범위이며 분산 잠금은 아니다.

추가 오류는 `503 MARKET_CACHE_UNAVAILABLE`이며 기존 400/429/502/503/504 계약은 유지한다. 가격 계약은 [가격 조회 문서](market-prices.md), 지표는 [운영 문서](backend-operations.md)를 참고한다.

## 검증과 근거

2026-10-04 [공식 Markets Swagger](https://developer-lostark.game.onstove.com/swagger-doc/endpoints/markets)의 MarketOption·Category·CategoryItem을 확인했다. 공개 명세 읽기와 인증 API 실호출을 구분하며 이번 작업에서 실제 인증 API를 호출하지 않는다.

로컬 모의 HTTP는 옵션 GET·인증·필드 매핑·누락 오류·429 공유 차단을 검증한다. 단위 테스트는 동시 16개 요청 병합, 수집 실패·캐시 장애 후 복구와 지표를 검증한다. Testcontainers Valkey와 실제 HTTP 통합 테스트는 TTL·출처/검색 조건별 키 분리·수집 시각 보존·만료 재조회·손상 복구·옵션 직렬화를 검증한다. 명세와 합성 `market-options.json`은 기존 CI 산출물에 포함된다.
