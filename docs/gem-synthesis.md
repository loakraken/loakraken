# 티어 4 보석 합성 계획

`POST /api/v1/gems/synthesis-plans`는 레벨별 보유 수량을 사용해 목표 레벨 보석을 만드는 계획을 계산한다. 성공은 `200 GEM_SYNTHESIS_PLAN_SUCCESS`다. 외부 API·캐시·DB를 호출하지 않고 입력만으로 계산한다.

## 확인한 공식 규칙

2026-10-04 [공식 보석 가이드](https://lostark.game.onstove.com/GameGuide/Pages/보석)와 [보석 합성 확률표](https://lostark.game.onstove.com/Probability/보석%20합성)를 확인했다. 같은 티어·같은 레벨 보석 3개로 한 단계 높은 보석 1개를 얻으며 결과 종류는 재료 종류와 무관하다. 공개 확률표의 티어 4 1→2부터 9→10까지 결과는 겁화·작열 각각 50%다. 이 페이지의 표시 수정일은 2024-07-10이며, 서비스의 확인일과 구분한다.

규칙 버전은 `t4-gem-synthesis-v1`, `rulesVerifiedOn`은 `2026-10-04`다. 응답의 `sources`에 위 두 공식 URL을 제공한다. 서비스가 매 요청마다 공식 페이지를 재검증하는 것은 아니다. 향후 규칙 변경 시 근거 확인·코드·회귀 테스트·버전을 함께 갱신한다.

목표는 **종류와 스킬을 구분하지 않는 티어 4 보석 수량**이다. 겁화 1개나 특정 스킬 보석의 확정 획득 계획이 아니다. `outcomesPerSynthesis`의 0.5는 새로운 합성 한 번의 종류별 확률이며 보유 보석의 종류나 목표 전체 달성 확률을 뜻하지 않는다. 합성이 필요 없는 계획에서도 규칙 참고값으로 반환한다.

### 광휘의 보석

2026-10-05 [공식 보석 가이드](https://lostark.game.onstove.com/GameGuide/Pages/보석)(표시 수정일 2026-06-24)를 다시 확인했다. 광휘의 보석은 티어 4 보석이며 겁화·작열을 대도시 NPC에서 광휘로 조율해 사용한다. 같은 레벨의 광휘/겁화/작열 보석 3개를 합성하면 상위 레벨의 겁화 또는 작열 1개를 얻는다.

- 이 계획은 종류를 구분하지 않는 티어 4 수량이므로 `inventory`에 광휘를 같은 레벨 수량으로 포함할 수 있다. 계산 규칙 `t4-gem-synthesis-v1`과 코드는 변경하지 않았다.
- 합성 결과는 광휘가 아니라 겁화 또는 작열이다. 광휘로 쓰려면 별도 조율이 필요하며, 조율과 15일 후 복원 조건은 계산하지 않는다.
- [합성 확률표](https://lostark.game.onstove.com/Probability/보석%20합성)의 표시 수정일(2024-07-10)은 광휘 안내보다 앞서며 광휘를 언급하지 않는다. 결과 확률 겁화·작열 각 50%는 이 확률표 기준이다.
- `rulesVerifiedOn`은 응답 계약값이므로 이번 문서 확인으로 바꾸지 않았다.

## 요청

```json
{
  "tier": 4,
  "baseLevel": 7,
  "targetLevel": 10,
  "targetQuantity": 1,
  "inventory": [
    {"level": 7, "quantity": 1},
    {"level": 8, "quantity": 2},
    {"level": 9, "quantity": 2}
  ]
}
```

| 필드 | 규칙 |
|---|---|
| tier | 필수, 4만 지원. 생략·다른 티어는 400 |
| baseLevel | 필수 정수, 1~9. 추가 확보량을 표현할 기준 레벨 |
| targetLevel | 필수 정수, baseLevel보다 크고 10 이하 |
| targetQuantity | 필수 정수, 1~1000 |
| inventory | 필수, 빈 배열 가능, 최대 10개. 레벨 중복·null 항목 불가 |
| inventory[].level | 필수 정수, baseLevel~targetLevel 범위 |
| inventory[].quantity | 필수 정수, 0~999999999. 이번 계획에 사용할 수 있는 보유 수량 |

누락한 레벨은 0개로 취급한다. 기준보다 낮거나 목표보다 높은 보석은 입력하지 않는다. 하위 보석의 부분 가치·상위 보석 분해·티어 전환은 제공하지 않는다. 소수 레벨/수량을 절삭하지 않고 400으로 거절한다.

## 계산과 실행 순서

목표 레벨부터 아래로 내려가며 필요한 개수에 보유 수량을 먼저 배정한다. 그 레벨의 부족분에 3을 곱해 바로 아래 레벨의 필요량을 구한다. 기준 레벨에서도 남은 부족분이 `additionalBaseQuantity`다. 합성 단위가 모두 3:1이고 종류를 구분하지 않는 조건에서 추가 기준 레벨 보석 수량을 최소화한다. 골드 비용이나 보석 효과의 기회비용을 최소화하는 계산은 아니다.

응답의 `inventory`는 기준~목표 레벨 전체를 오름차순으로 반환한다. `providedQuantity`, `usedQuantity`, `remainingQuantity`는 **기존 보유분**의 배정이며 중간 합성 결과를 재고로 다시 세지 않는다. `ownedTargetUsed`는 보유 목표 보석 중 계획에 배정한 개수, `newTargetQuantity`는 새로 합성할 목표 보석 개수다.

`steps`는 실제 실행할 낮은 레벨부터 높은 레벨 순서다. 각 행은 `inputLevel`, `outputLevel`, `inputQuantity`, `outputQuantity`이며 입력 수량은 출력 수량의 3배다. 출력 개수는 그 단계의 합성 횟수와 같다. `synthesisCount`는 단계별 출력 개수의 합이다.

위 예시는 7레벨 2개를 추가하면 실행할 수 있다. 보유 7레벨 1개와 추가 2개 → 8레벨 1개, 기존 8레벨 2개와 합성 결과 1개 → 9레벨 1개, 기존 9레벨 2개와 합성 결과 1개 → 10레벨 1개다. 전체 합성은 3회다. 추가 확보분을 얻기 전에는 모든 단계를 실행할 수 있는 상태가 아니다.

| status | 의미 |
|---|---|
| READY | 입력 수량만으로 계획 가능. additionalBaseQuantity=0 |
| MISSING_BASE_GEMS | 기준 레벨 보석 추가 확보 필요. steps는 확보 이후의 조건부 계획 |

보유 목표 레벨 보석만으로 충당되면 `steps=[]`, `synthesisCount=0`이고 낮은 레벨 보유분을 소모하지 않는다. 1레벨에서 10레벨 1000개를 보유량 없이 만들 때는 추가 1레벨 보석 19,683,000개·합성 9,841,000회다. 수량만 정수 연산하며 보석 개수만큼 반복하거나 확률 시뮬레이션을 실행하지 않는다.

## 한계와 검증

READY는 입력 수량으로 계산한 상태다. 티어 4 합성에 필요한 캐릭터 아이템 레벨 1640, 잠금·장착·이벤트 제한, 실제 보유량과 합성 가능 여부를 검증하지 않는다. 사용자는 합성 가능한 보석만 입력해야 한다. 게임 내 합성을 실행하거나 자동 조작하지 않는다.

경매장 가격·합성 대비 직접 구매 비용·종류/스킬별 기대 시도·DPS·보석 승급·조율·지원 보석은 계산하지 않는다. 거래소 재료 견적에 경매장 보석 가격을 섞지 않는다.

도메인 테스트는 혼합 재고·목표 레벨 재고 충당·최대 수량을 검증한다. 작은 입력 324개 조합에서 추가 보석을 0개부터 늘리는 정방향 합성과 최소 추가량을 대조하고, 출력 순서대로 실행해 모든 레벨의 수량이 보존되는지 확인한다. 실제 HTTP 테스트는 입력 범위·중복·소수 절삭 거절·티어 지정과 상태 응답을 확인한다. Swagger 필수 필드와 `gem-synthesis-plan.json`, `gem-synthesis-ready.json` 합성 응답을 CI 산출물로 보관한다.
