# 캐릭터 스냅샷

관측 저장과 이력 조회는 `CHARACTER_SNAPSHOTS_ENABLED=false`가 기본값입니다.
비활성 상태에서는 검색 성공 시 스냅샷 저장소와 DB 트랜잭션을 호출하지 않고 단기 캐시만 반영합니다.
기존 DB 데이터를 삭제하지 않으며 DB/Flyway 등 애플리케이션 시작 의존성은 유지합니다.
이력 API는 `503 CHARACTER_HISTORY_DISABLED`를 반환합니다.

공식 가이드의 캐시 권장과 약관의 콘텐츠 보관 조항 사이에서 장기 보관·재제공 허용 범위는 확인되지 않았습니다.
짧은 TTL이나 정규화만으로 허용된다고 단정하지 않습니다. 근거와 미확정 사항은
[공식 자료 교차 검증](source-verification.md)에 정리했습니다.
합성 데이터 개발 환경 또는 보관·재제공 범위를 확인한 환경에서만 실행 환경 변수로 `CHARACTER_SNAPSHOTS_ENABLED=true`를 지정합니다.
Spring Boot는 `.env`를 자동으로 읽지 않습니다. 설정 변경은 재시작 시 적용됩니다.

아래는 **활성 상태의 동작**입니다. 외부 종합 조회가 성공하면 짧은 DB 트랜잭션으로 관측 정보를 저장한 뒤 캐시에 반영합니다.
캐시 적중은 DB 저장과 외부 호출을 모두 생략합니다. 저장 실패는
`503 CHARACTER_STORAGE_UNAVAILABLE`이며 새 캐시를 만들지 않습니다.
DB 커밋 뒤 캐시 저장이 실패하면 DB 기록은 남고 요청은 캐시 오류로 종료합니다.
다음 요청이 같은 원본을 다시 수집해도 중복 스냅샷은 만들지 않습니다.

## 저장 내용

- `characters`: 내부 UUID, 관측 캐릭터명·서버·직업, 아이템 레벨·전투력, 마지막 확인 시각
- `character_snapshot`: 내부 UUID, 스키마 버전, 원본 Armories·Siblings JSONB, 수집 시각, 저장 시각
- 원본에는 미해석 Tooltip과 이후 추가된 공식 필드도 남습니다. 인증 헤더는 저장하지 않습니다.
- 공개 응답과 Valkey에는 정제된 조회 결과만 저장합니다.

Flyway의 `V1__create_character_snapshots.sql`이 스키마를 만듭니다.
JSONB 변환으로 공백·객체 키 순서는 보존되지 않지만 필드와 값은 유지합니다.
원본 보존은 전투정보 필터로 요청한 응답 범위이며 아바타·스킬·수집품 등 미요청 섹션을 수집했다는 의미는 아닙니다.

## 중복과 동시성

서버·캐릭터명의 유일 제약과 PostgreSQL UPSERT의 행 잠금으로 저장을 직렬화합니다.
바로 이전 원본 두 문서가 JSONB 비교로 같으면 스냅샷 추가를 생략하고 마지막 확인 시각만 갱신합니다.
예전과 같아졌더라도 중간 변경이 있었다면 새 이력을 남깁니다.
동일 수집 시각의 순서는 DB 시퀀스로 구분하며, 더 오래된 수집 결과는 최신 관측을 덮어쓰지 않습니다.

정책 확인 후 호출하는 PostgreSQL 저장 어댑터에 3초 제한의 `@Transactional`을 사용합니다.
외부 HTTP 요청과 캐시 I/O는 해당 트랜잭션에 포함하지 않습니다.
JDBC의 매개변수 바인딩을 사용하며 PostgreSQL UPSERT·JSONB 비교를 명시적으로 수행합니다.

## 한계와 후속 작업

공식 불변 식별자가 없으므로 이름 변경·서버 이동 전후를 자동 연결하지 않습니다.
변경 없는 갱신은 스냅샷 행을 만들지 않기 때문에 이 테이블은 모든 조회 시도를 기록하는 감사 로그가 아닙니다.
프로필 관측 이력 API는 구현되어 있지만 저장 기능과 함께 기본 비활성 상태입니다.
보존 기간별 삭제 작업은 아직 없습니다. 기존 데이터를 자동 삭제하지 않는다는 구현 사실이 영구 보관 허용을 뜻하지 않습니다.
여러 애플리케이션 인스턴스를 운영하려면 공유 호출 제한과 캐시 갱신 조정이 별도로 필요합니다.
