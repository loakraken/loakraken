# 전투력 시뮬레이터 (combat-power-sim-v6)

로아랩(lo4.app) 전투력 시뮬레이터와 같은 기능이다(PM 총괄 방향 전환 10-10: 중복 기능은 로아랩 기준). 캐릭터의 현재 세팅에서 보석·재련·품질·연마·팔찌·각인·스톤·아크 패시브·아크 그리드 코어를 바꿨을 때 전투력이 얼마나 오르는지 보여 준다.

A단계는 **계약과 입력 검증만** 연다. 전투력 계산식은 계산 검증 팀이 목표 사이트 실측 대조로 항목별로 확정한 뒤(B단계부터) 채운다. 확정 전 항목은 값 없이 `UNSUPPORTED`로 알린다(추정 금지, 계산 일치 원칙).

- 플래그 `combat-power-sim.enabled`(환경 변수 `COMBAT_POWER_SIM_ENABLED`), 기본 false. 끄면 두 경로와 OpenAPI 계약에서 모두 빠진다.
- 운영은 보석·재련·각인 계산식이 계산 검증을 통과한 뒤에만 켠다(PM 총괄 10-10).
- **공식 API를 부르지 않는다.** 캐릭터 캐시(검색 API가 채움)만 읽는다. 요청 버킷은 GENERAL이다.

## `GET /api/v1/characters/combat-power/options`

화면 입력의 허용 범위다. 고정 값이라 캐릭터·`fetchedAt`이 없다.

- `verified=false`면 숫자 범위가 공식 근거로 확정되기 전 예시다. B단계에서 공식 표로 채우고 true로 바꾼다.
- `polishValues`(#251): 고대 장신구 연마 옵션별 하·중·상 수치. 값은 공식 툴팁 표기 그대로(`"+2.60%"`, `"+390"`)이고, `percent`로 같은 이름의 % 옵션과 고정값 옵션(공격력·무기 공격력)을 가른다.
  - 근거: 공식 armory 장비 툴팁 30명 표본(2026-10-10). 등급은 연마 줄 글자색(#FE9600 상·#CE43FC 중·#00B5FF 하)으로 읽고, 옵션·등급마다 값이 하나뿐인지 확인했다. 리소스 `combat-power/polish-values.json`.
  - 표본에 그 등급 줄이 없던 칸은 null이다(아군 피해량 강화 중, 최대 마나 상, 전투 중 생명력 회복량 상). 유물 장신구는 같은 옵션도 값이 달라 아직 넣지 않았다.
  - 팔찌 등급 수치는 표본을 늘려 따로 추가한다(특수 효과는 등급마다 값이 하나지만 30명 표본으로는 칸이 다 차지 않고, 치명·신속 같은 특성 줄은 등급 안에서 값이 흩어진다).
- 표본: `build/generated/combat-power-options.json`(통합 테스트가 만듦).

## `POST /api/v1/characters/combat-power/simulate`

```json
{"characterName":"모험가","changes":[
  {"kind":"GEM_LEVEL","slot":0,"level":10},
  {"kind":"EQUIPMENT_REFINE","index":0,"refine":22}
]}
```

`changes`는 최대 64개이고 빈 목록도 된다. 같은 대상을 두 번 바꾸면 뒤의 변경이 이기고, 자리는 처음 나온 곳을 지킨다.

| kind | 대상 | 바꿀 값 | 범위(예시) |
|---|---|---|---|
| `GEM_LEVEL_ALL` | 보석 전체 | `level`(0은 모두 빼기) | 0–10 |
| `GEM_LEVEL` | `slot`(검색 응답 gems.items[].slot) | `level`(0은 빼기) | 0–10 |
| `EQUIPMENT_REFINE` | `index`(검색 응답 loadout.equipment 순번, 무기·방어구) | `refine` | 10–25 |
| `EQUIPMENT_ADVANCED_REFINE` | `index`(무기·방어구) | `level` | 0–40 |
| `EQUIPMENT_QUALITY` | `index`(품질이 있는 장비) | `quality` | 0–100 |
| `POLISH` | `index`, `line`(연마 효과 줄, 0부터) | `option`, `grade`(LOW·MID·HIGH) | |
| `BRACELET_EFFECT` | `line`(팔찌 효과 줄, 0부터) | `name`, `grade`(LOW·MID·HIGH) | |
| `ENGRAVING_LEVEL` | `name`(아크 패시브 각인 이름) | `level` | 0–4 |
| `STONE_ENGRAVING` | `name`(스톤 각인 이름) | `level` | 0–4 |
| `ARK_PASSIVE_POINT` | `tree`(진화·깨달음·도약) | `points` | 0–999 |
| `ARK_GRID_CORE` | `slotIndex`(아크 그리드 slot index) | `grade`(영웅·전설·유물·고대), `point` | 0–20 |

## 응답

| 필드 | 의미 |
|---|---|
| `fetchedAt` | 현재 세팅을 읽은 캐릭터 캐시의 수집 시각. 웹은 검색 응답 `fetchedAt`과 다르면 다시 불러온다 |
| `before` | 공식 전투력(armory CombatPower). 없으면 null |
| `modelBefore` | 현재 세팅의 모델값(계산 검증·QA용, 화면 표시 안 함). 계산식 확정 전 null |
| `after` | 바꾼 항목 중 `OK` 항목을 함께 적용한 전투력 |
| `delta`, `deltaPercent` | `after - before`, `delta / before × 100`(%) |
| `partial` | `UNSUPPORTED` 항목이 있어 `after`가 일부 변경만 반영했으면 true |
| `contributions[]` | 바꾼 항목별 `kind`·`target`·`from`·`to`·`delta`·`status`(OK·UNSUPPORTED)·`basis` |
| `unsupportedCount` | `UNSUPPORTED` 항목 수 |

- **after 계산(B단계부터)**: `after = before × model(바꾼 세팅) / model(현재 세팅)`. 공식 전투력에 모델 비율을 곱해, 모델이 공식 값과 조금 달라도 증가율은 모델 기준으로 맞춘다(PM-백엔드 18:27).
- **contributions[].delta**: 바꾼 항목을 순서대로 하나씩 적용했을 때의 증가분이다. `OK` 항목 delta의 합은 `delta`와 같다. 순서를 바꾸면 항목별 delta는 달라질 수 있지만 합은 같다.
- 응답 `kind`는 요청 kind와 같은 문자열이고 응답에서는 enum으로 고정하지 않는다. 새 kind가 생겨도 웹은 모르는 kind를 이름 그대로 보여 준다.
- `basis`에는 다른 사이트 이름을 쓰지 않는다.
- **반올림은 서버에서 끝낸다**: 전투력 값은 소수 둘째 자리, `deltaPercent`는 소수 셋째 자리(HALF_UP).
- 표본: `build/generated/character-combat-power-simulate.json`(통합 테스트가 만듦).

## 성능

캐시 1회와 공개 제외 1회만 읽는다. 목표는 p95 200ms 이하다(PM-프론트 18:31). 입력 디바운스 300ms면 사용자 1명이 분당 최대 200회라 GENERAL 버킷(분당 240회) 안이다.

## 보석 계산 (combat-power-sim-v1)

`GEM_LEVEL`·`GEM_LEVEL_ALL`은 `OK`로 계산한다. 근거는 리소스 `combat-power/gem-coefficients.json`(출처·확인 날짜 포함)과 볼트 「전투력 검증 준비」 7·8절이다.

- 식: `전투력 비 = Π(1 + 보석 배수) × (1 + 기본 공격력 % 합)`. `after = before × 비(바뀐 세팅) / 비(현재 세팅)`.
- 보석 배수(4티어 겁화·작열·광휘 공통, 칸마다 곱): 1~10레벨 1.28·1.92·…·7.04%(`0.64 × (레벨 + 1)`). 출처는 인벤 「딜러 전투력 로직 분석」(https://www.inven.co.kr/board/lostark/4821/106546).
- 기본 공격력 %는 공식 툴팁 세 곳에서만 모은다.
  - 보석 효과 `기본 공격력 n% 증가`: 6레벨 0.45, 7레벨 0.60, 8레벨 0.80, 9레벨 1.00, 10레벨 1.20.
  - 어빌리티 스톤 `[레벨 보너스] 기본 공격력 +n%`.
  - 완갑 `추가 효과`의 `기본 공격력 +n%`.
- 교차 검증: 목표 사이트(로아랩) 딜러 전투력 시뮬레이터에서 5명 30건(보석 빼기, 6~10레벨, 전체 바꾸기)을 대조했고 모두 ±0.01 안에서 맞는다(계산 검증 #244, `src/test/resources/verification/combat-power/loalab-gem-deltas-2026-10-10.json`). 남은 0.01은 공식 전투력이 소수 둘째 자리까지만 와서 생기는 반올림이다.
- 아래 경우는 추정하지 않고 `UNSUPPORTED`로 두고 이유를 `basis`에 쓴다.
  - 세 곳 밖에서 `기본 공격력 n%` 문구가 나올 때(장비·아크 패시브·아크 그리드·각인)
  - 보석의 공식 표기가 계수표와 다를 때
  - 3티어 보석(멸화·홍염)이 있을 때(배수를 표본으로 아직 확인하지 않음)
  - 1~5레벨로 바꿀 때(기본 공격력 % 근거 없음)
  - 공식 전투력이 없을 때
- 보석 빼기는 `level` 0이다(배수 0, 기본 공격력 0). #244 표본의 빼기 10건으로 확인했다. `to`는 "0"이다.

## 품질·각인·스톤 계산 (combat-power-sim-v2, #275)

모두 독립 배수라 전투력 비 = Π 항목 배수이고, `after = before × 비(바뀐 세팅) / 비(현재 세팅)`이다. 근거는 리소스 `combat-power/equipment-engraving-coefficients.json`과 `docs/verification/combat-power.md` 「장비·각인·스톤 변화량」이다. 계산 검증 표본 5명 38건 중 식이 확정된 27건을 테스트 기대값으로 쓴다(±0.01).

| 항목 | 배수 | 계산하지 않는 경우 |
|---|---|---|
| 무기 품질(`EQUIPMENT_QUALITY`, 무기) | `(1 + 추가 피해(새)) / (1 + 추가 피해(현재))`, 추가 피해 = `10 + 20 × (품질/100)²`(반올림 없음, v3, 계산 검증 10-11 17:25). 공식 툴팁 숫자는 이 값의 올림이라 쓰지 않는다 | 품질을 모를 때 |
| 방어구 품질(투구·상의·하의·장갑·어깨) | 1(전투력 변화 없음, 체력에만 붙음) | — |
| 그 밖 품질(장신구 등) | — | 항상 |
| 원한·저주받은 인형·질량 증가·타격의 대가(`ENGRAVING_LEVEL`·`STONE_ENGRAVING`) | `1 + v`, `v = 기본(18·14·16·14) + 0.75 × 각인서 레벨 + 스톤 가산(0·3.00·3.75·5.25·6.00)` | 유물이 아닐 때, 공식 설명값이 표와 다를 때 |
| 아드레날린 | `1 + 6 × 중첩당 공격력(스톤 0~4: 0.90·1.38·1.50·1.73·1.85) + 0.7 × (14 + 1.5 × 각인서 레벨)` | 같음 |
| 돌격대장 | `1 + 0.40 × v`, `v = 40 + 2 × 각인서 레벨 + 스톤 가산(2·3·4: 9.4·13.2·15.0)` | 스톤 1(공식 값 없음) |
| 그 밖 각인(예리한 둔기 등)·상급 재련 | — | 항상 |

- **현재 값 확인**: 각인의 현재 각인서·스톤 레벨로 만든 값이 공식 각인 설명(ArkPassiveEffects Description)에 그대로 있어야 계산한다. 예: 원한 L0 S2 → "21.75%". 다르면 계수표를 믿지 않는다.
- **스톤 [레벨 보너스]**: 스톤 레벨을 바꾸면 합이 바뀐다. 바뀌기 전·후 합이 모두 5~7일 때만 계산한다(그 구간에서는 보너스가 그대로임을 확인). 벗어나면 이유를 basis에 쓰고 계산하지 않는다.
- 같은 각인의 각인서·스톤을 함께 바꾸면 순서대로 합쳐 계산한다.

## 재련 단계 계산 (combat-power-sim-v4, #319)

계산 검증 10-11 18:05 모델 확정(대조 사이트 서버 계산과 비율 오차 2e-7 이하). 근거·단계표는 리소스 `combat-power/refine-coefficients.json`, 표본은 `src/test/resources/verification/combat-power/loalab-refine-model-2026-10-11.json`이다.

- 공식 기본 공격력 B = (R + F)(1 + q), R = √(S·W/6), S = 6R²/W.
  - B: 프로필 `공격력` Tooltip의 "기본 공격력은 N"
  - F: 팔 보호구 기본 효과 "기본 공격력 +N"(팔 보호구가 없으면 0)
  - q: 기본 공격력 %(보석 + 스톤 레벨 보너스 + 팔 보호구 "+x%"), 보석 모델과 같은 값
  - W: (무기 "무기 공격력 +N" + 팔 보호구 "무기 공격력 +N" + 장신구 연마 "무기 공격력 +N") × (1 + 장신구 연마 "무기 공격력 +x%" + 깨달음 카르마 레벨 × 0.1%). 카르마 레벨은 깨달음 포인트 설명 "6랭크 29레벨"의 29다.
- 방어구 단계: S' = S + Δ주스탯 × mS, mS = 1 + 펫 1%(가정) + 아바타(무기·머리·상의·하의 아바타 부위마다 가장 높은 등급, 전설 2%·영웅 1%)
- 무기 단계: W' = W + Δ무기 공격력 × (1 + 무기 공격력 %)
- 전투력 비 = (R·√(S'/S · W'/W) + F)/(R + F). 여러 부위를 함께 바꾸면 S'·W'에 모두 더한다.
- **펫 가정**: 펫 효과(힘민지 +1%)는 공식 응답에 없어 있다고 가정한다(두 출처가 같은 가정). 펫이 없으면 방어구 단계 변화량만 약 0.92% 작아진다(무기 단계·현재 전투력은 영향 없음). basis에 가정을 적는다.
- **계산하지 않는 경우**(이유를 basis에)
  - 전율이 아닌 장비(업화·에스더 무기): 단계표를 아직 확인하지 않음
  - 11~25 밖의 단계
  - 공식 기본 공격력·무기 공격력·팔 보호구 기본 공격력·깨달음 레벨을 읽지 못할 때
  - q를 확정하지 못할 때(보석 모델이 계산하지 않는 세팅)
  - 팔찌에 무기 공격력 효과가 있을 때, 등급 계수를 모르는 아바타가 있을 때
  - 상급 재련(`EQUIPMENT_ADVANCED_REFINE`)·팔 보호구 단계: 계산식 미확인
- 기대값 테스트(±0.01): 언새늘 투구 19→20 = 3,352.32, 무기 19→20 = 3,383.60, 19→25 = 3,583.14, 19→16 = 3,233.15 / inzai 투구 25→24 = 11,007.13, 25→19 = 10,907.74 / 만배 투구 25→24 = 10,703.41.

## 상급 재련과 업화 장비 단계 (combat-power-sim-v6, #333)

PM 총괄 판정 (b), 표본 `loalab-advanced-refine-2026-10-11.json`, 계수 `combat-power/refine-coefficients.json`(upgrade*).

- 업화 장비 수치 = round(T(5 × 일반 재련 + 상급) × (1 + 30단계 2% + 40단계 3%)). 일반 재련 1단계 = 상급 5단계로 같은 표 위에 있다.
  - 방어구 T = round(투구 T × 부위 배수(상의 0.8·하의 0.86428·장갑 1.2·어깨 1.06429)). 5의 배수 사이 칸은 투구 세부표(110~149) 또는 ⌈T(a) + (T(a + 5) − T(a)) × f(j)⌉(f = 0.1971·0.3958·0.5958·0.7971, 실측 칸과 ±1 스탯).
  - 무기는 확인된 칸(weaponExactT 68칸)만 계산하고, 나머지는 "이 단계 조합의 무기 수치를 아직 확인하지 않아 계산하지 않았습니다"로 UNSUPPORTED다.
- `EQUIPMENT_REFINE`(업화 일반 재련)과 `EQUIPMENT_ADVANCED_REFINE`(상급) 모두 이 표로 수치 차이를 구하고, 전투력은 재련 모델의 S·W 식 그대로다. 같은 요청에서 일반·상급을 함께 바꾸면 한 칸으로 합친다.
- 전율 장비의 상급 재련, 그 밖의 장비(에스더 등)는 UNSUPPORTED다.

## 팔찌 계산과 전투력 기여 (combat-power-sim-v5, #327)

계산 검증 10-11 21:00 모델 확정, 표본 `loalab-bracelet-2026-10-11.json`, 계수 리소스 `combat-power/bracelet-coefficients.json`.

- 팔찌 효과 줄마다 독립 배수다. 공식 툴팁은 효과마다 아이콘으로 나뉘므로 두 문장짜리 옵션도 한 줄이다.
  - 특수 옵션 13계열 × 하·중·상: (1 + 계수/100). 옵션은 **공식 문구 속 숫자로** 판단한다("3%"와 "3.0%"는 같은 옵션). 추가 피해 +3.50%(중) = 2.6922.
  - 전투 특성(치명·특화·신속): 프로필 세 값의 합 T에 대해 전투력 ∝ (1 + 0.0003·T). 여러 줄은 T에서 함께 뺀다(만배 16.86, 계산 검증 정정).
  - 팔찌 도약 포인트: 도약 합 P에 대해 (1 + 0.002·P)
  - "무기 공격력 +N"과 "무기 공격력이 N 증가한다"의 고정 N: 재련 모델 W 항(버프 부분은 넣지 않음, 계산 검증 23:45). 재련 단계 계산도 이 N을 W에 넣는다.
  - 제압·인내·숙련, 공이속·방어·생명력·회복·전투자원 등: 0
- `BRACELET_EFFECT`: `line`(0부터)을 `name`(`options.braceletOptions`의 계열 이름) + `grade`(LOW·MID·HIGH)로 바꾸거나, `name: "없음"`으로 뺀다. 바꾸는 줄만 비율에 들어가므로 모르는 줄이 있어도 그 줄을 건드리지 않으면 계산한다.
- 계산하지 않는 경우: 바꾸는 줄이나 새 옵션을 모를 때(이유를 basis에), 전투 특성 합을 읽지 못할 때, 전투 특성 줄을 다른 전투 특성으로 바꿀 때(등급별 수치 미확인).
- **전투력 기여**: `GET /api/v1/characters/combat-power/contributions?characterName=`. 그 항목을 뺐을 때 공식 전투력이 몇 % 줄어드는지(1 − 뺀 전투력/지금 전투력)다. 지금은 팔찌(효과 줄 전부 + 팔찌 도약)만 주고, kind는 문자열이라 아크 그리드 등이 늘어난다. 기대값: 언새늘 12.60·만배 16.86·inzai 15.38.

## 단계

- **A단계**(#240): 계약·검증·표본. 모든 항목 `UNSUPPORTED`.
- **B단계**: 계산 검증이 확정한 항목부터 `OK`로 바꾼다. 보석(완료) → 품질·각인·스톤(완료) → 재련(완료, #319) → 팔찌(완료, #327) → 상급 재련·업화(완료, #333, 무기는 확인된 칸만) → 아크 그리드 → 연마 → 아크 패시브 순. 각 항목은 목표 사이트 실측(기준 캐릭터 언새늘)과 맞아야 한다. 맞지 않는 차이가 설명되지 않으면 P0다.
- 상급 재련의 현재 단계(`from`)는 검색 응답 `advancedRefineLevel`(#234)이다.
