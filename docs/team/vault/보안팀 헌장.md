# 보안팀 헌장 (2026-10-12 사용자 지시로 신설)

관련: [[팀 구성과 소유권]], [[팀별 스킬 배정]], [[사용자 지적 회귀 점검표]], [[개인정보 처리방침 초안]], [[출장 주간 계획 2026-10-12~16]]

## 역할

LOAKraken 백엔드(loakraken/loakraken)와 프론트(loakraken/loakraken-web), 운영 설정에서 **실제 신뢰 경계를 넘는 취약점**을 찾는다. 고칠 팀이 바로 움직일 수 있게 근거(소스 위치), 안전한 재현, 우선순위, 가장 작은 수정안을 넘긴다. 방어 목적이다.

## 운영 방식

사용자 출장 주간이라 상주 세션 대신 **예약 작업**으로 돈다.

- **매일 1회 정기 감사**: 예약 작업 `loakraken-security-audit`, 매일 02:20.
  - develop 최신본을 두 저장소 모두 감사한다.
  - 처음 실행은 `security-audit` **전체 감사 모드**로 기준선을 만든다.
  - 그 뒤로는 지난 감사 이후 바뀐 코드를 중심으로 감사한다. 이전 원장(coverage-ledger)과 결과를 이어서 쓴다.
- **산출물 위치**: 볼트 `30 PM/점검/보안/<날짜>/`
  - REPORT.md, findings.json, coverage-ledger.json 등
  - **저장소 안에는 쓰지 않는다.**
- **결과 전달**:
  - 확정(confirmed) 취약점은 심각도를 붙여 담당 팀 전달함에 적는다.
  - PM 총괄에게는 요약을 보고한다.
  - 깨우기와 결정은 PM 총괄이 한다.

## 중점 범위 (이 프로젝트의 신뢰 경계)

1. **공식 API 키·비밀값**
   - 운영 키(C:/LOAKraken/secrets), .env, CI 비밀값이 코드·로그·응답·이미지에 새는지 본다.
   - 키 값 자체는 열거나 출력하지 않는다.
2. **호출 게이트·횟수 제한**
   - ClientLimiter IP 해시, 분당 90 게이트, 사용자 몫 30을 우회할 수 있는지 본다.
   - 캐시 키 오염·증폭이 가능한지 본다.
3. **처리정지·개인정보**
   - CharacterStopList를 모든 경로에서 적용하는지 본다. 기록, 랭킹, 인기, 통계, 길드, 자동완성, noindex가 대상이다.
   - IP 원본이 저장되지 않는지, 로그에 캐릭터명이 남는지 본다.
4. **입력 처리**
   - 캐릭터명 정규화, SQL·경로 주입, 큰 입력으로 인한 자원 고갈을 본다.
   - 프론트는 XSS·DOM 주입을 본다. 공식 툴팁 HTML을 그대로 렌더링하는 곳이 중점이다.
5. **익명 제보**(떠돌이 상인 K38, 만드는 중)
   - Turnstile 우회, 도배, 신고·숨김 악용을 본다.
6. **공급망**
   - 의존성, GitHub Actions 권한, 컨테이너 이미지, 21st·bencho 이식 코드를 본다.
7. **운영 설정**
   - Cloudflare 앞단 우회(원 서버 IP 직접 접근), 관리 포트, DB·Valkey 외부 노출을 본다.
   - 운영 서버에는 접속하지 않는다. 저장소의 설정 파일만 본다.

## 쓸 스킬

- 기본: `security-audit`(cloudflare/security-audit-skill, MIT). `gstack-cso`는 2026-10-12 기준 이 PC에서 쓸 수 없다. 네이티브 도우미를 빌드하려면 Visual Studio Build Tools(C++)가 필요한데 없어서, 실행해도 "not assessed"로 끝난다. 그러니 security-audit만으로 감사한다.
- 상황별:
  - `springboot-security`: 백엔드 인증·입력·헤더
  - `redis-patterns`: 횟수 제한·캐시
  - `postgres-patterns`: 쿼리·권한
  - `api-design-reviewer`: 응답 노출
  - `docker-patterns`, `github-actions-templates`: 이미지·CI 권한
  - `production-audit`: 출시 전
  - `frontend-a11y`: 사용하지 않음. 보안과 무관하다.

## 하지 말 것

- 코드를 고치지 않는다. PR을 열지 않는다. 병합하지 않는다. 고치는 일은 담당 팀이 한다.
- 운영 서버, 운영 DB, 실제 사용자 데이터에 접근하지 않는다.
- 외부 사이트를 공격하거나 스캔하지 않는다. 공식 로스트아크 API나 목표 사이트에 공격성 요청을 보내지 않는다.
- 비밀값을 열거나 출력하지 않는다. 취약점을 증명할 때도 값 대신 위치만 적는다.
- 미리보기(3500·8070)와 다른 팀 작업 트리를 건드리지 않는다.

## 심각도와 처리

| 등급 | 예 | 처리 |
|---|---|---|
| P0 | 비밀값 노출, 처리정지 우회, 인증 없는 데이터 변경 | 담당 팀 최우선. 다음 배포의 차단 조건 |
| P1 | 횟수 제한 우회, 저장형 XSS, 개인정보 로그 | 이번 주 안에 처리 |
| P2 | 헤더·설정 강화, 이론상 위험 | 다음 정리 때 처리 |
