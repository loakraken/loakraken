# 공식 자료 및 경쟁 서비스 교차 검증

검증일: 2026-10-04 KST. 전달받은 분석의 주장은 참고 자료로 취급하고 아래 공식 페이지·명세와 현재 코드를 직접 대조했다. 검색 수집본과 실제 기능 실행 검증은 구분한다.

## 공식 API의 저장 범위

[사용 가이드](https://developer-lostark.game.onstove.com/usage-guide)는 캐시를 권장하고 뉴스·이벤트·옵션 데이터의 갱신 주기를 예로 든다. 이 예시가 캐릭터 원본의 장기 보관 기간을 승인한 것은 아니다. [약관](https://developer-lostark.game.onstove.com/agreement)은 콘텐츠 보관·복제·배포를 폭넓게 제한하는 문구를 포함한다. 두 문서만으로 캐릭터 원본의 장기 보관과 과거 이력 재제공 허용 범위를 확정할 수 없다.

따라서 “원본을 짧게 보관하고 정규화 데이터는 계속 저장하면 허용된다”는 결론은 채택하지 않는다. 정규화·파생 값의 예외나 허용 TTL은 확인되지 않았다. 이는 법적 허용/금지 판정이 아니라 확인되지 않은 전제를 구현 정책에서 분리한 결정이다.

- `CHARACTER_SNAPSHOTS_ENABLED=false`를 기본값으로 두고 원본 및 characters 행 신규 저장, 과거 이력 공개를 함께 중지한다. 기존 데이터는 그대로 보존한다.
- 단기 조회 캐시 5분은 호출 부담을 줄이기 위한 기술 설정이다. 공식 승인 기간을 뜻하지 않는다. 캐시 응답도 약관 확인 범위에 포함한다.
- 활성 저장의 자동 삭제 기능은 아직 없으므로 플래그를 켜는 것만으로 보존 정책이 해결되지 않는다.
- 실제 API 테스트는 DB 스냅샷 및 응답 파일 저장을 끈다. 합성 데이터 테스트로 저장·롤백·이력 계약을 검증한다.

운영 전 확인할 범위는 원본 JSONB, 정규화 프로필·장비, 파생 진단·점수, 각 보존 기간, 과거 수치 재제공, 캐시, 삭제 요청 처리다. 문의 초안은 내부 기록에 남기며 메일을 발송하지 않았다.

## 최신 경로와 버전의 의미

[변경 이력](https://developer-lostark.game.onstove.com/changelog)의 V10 설명에는 `POST /market/trades`라고 적혀 있지만, 공개 [Markets Swagger](https://developer-lostark.game.onstove.com/swagger-doc/endpoints/markets)의 실제 경로는 **`POST /markets/trades`**이고 operationId는 `Markets_GetTrades`다. 공식 공개 명세를 직접 HTTP 조회해 확인했으며 인증 API는 호출하지 않았다. 거래 가격 도입 시 현재 명세를 기준으로 다시 검증해야 한다.

| 구분 | 확인된 의미 | 구현 기준 |
|---|---|---|
| 변경 이력 V10.0.0 | 공개 릴리스 변경 묶음 | 개별 응답에서 관측한 버전처럼 저장하지 않는다 |
| Markets Swagger info.version v1 | 해당 명세의 메타데이터 | 릴리스 V10과 동일 개념이 아니다 |
| DB schema_version 1 | 내부 스냅샷 저장/해석 형식 | 외부 API 버전으로 표시하지 않는다 |
| diagnostics.ruleVersion observed-v2 | 원천 제공 상태를 반영한 관측 진단 규칙. 최초 검증 당시 observed-v1에서 갱신 | 원천 수집 시각 fetchedAt과 분리한다 |

변경 이력에서 V9의 ArkGrid, V8의 CombatPower도 확인했다. 가이드의 과거 예시 경로를 현재 엔드포인트 존재의 근거로 사용하지 않는다. 향후 매핑 버전과 규칙 버전은 각각 관리하되, 지금 고정 문자열 V10을 모든 응답의 출처 버전으로 붙이지 않는다.

## 경쟁 서비스 주장 보완

- [LOPEC 공식 공지](https://lopec.kr/)는 성장 가이드·목표 경로·시뮬레이션뿐 아니라 2026-03-16 원정대 주간 골드·간단 체크리스트·로그 추가도 안내한다. 단순 스펙 점수 사이트로 축소하지 않는다. 수식과 가정을 설명한다는 이유만으로 독점적 차별화라고 주장하지 않는다.
- [ILOA 통계](https://iloa.gg/statistics)는 등록된 캐릭터를 모집단으로 설명하고 집계 수와 시각을 표시한다. 조회된 문서에는 4,759,883개, 2026-09-23 07:30 KST가 표시되었다. 이는 조회 시점의 실시간 전체 유저 수가 아니다. 홈 카운터와 통계 모집단을 섞지 않는다. [랭킹](https://iloa.gg/ranks), [도구](https://iloa.gg/tools) 진입점도 확인했다.
- [RLoA 개발 사이트](https://dev.rloa.gg/)의 검색 수집본에는 메뉴와 접속 인원 문구가 있지만, 직접 조회 본문은 추출되지 않았다. 개발 사이트 검색 인덱스는 운영 서비스 정상 작동이나 현재 동접 수의 증거가 아니다.
- 동일 캐릭터의 실시간 수치·계산 결과 비교와 브라우저 상호작용은 여전히 미검증이다. 상세 목록은 [비교 대상 검증](reference-sites.md)에 있다.

## 현재 코드와 대조한 설계 제안

| 제안 | 현재 상태 및 결정 |
|---|---|
| 관측·파생·진단·추천·시뮬레이션 분리 | 현재 profile/loadout → analysis → diagnostics로 나뉜다. 추천·DPS·비용 수식은 근거 확보 전 구현하지 않는다 |
| 조회 상태와 값의 의미 분리 | 현재 두 원천 요청 모두 성공해야 검색 성공이다. 누락 섹션이 곧 HTTP 부분 실패는 아니다. PARTIAL 응답은 실제 부분 성공 정책을 설계할 때 도입한다 |
| null과 미착용 구별 | 주요 섹션과 최상위 목록의 정규화 전 상태를 coverage로 보존하고 observed-v2 진단에 연결했다. 깊은 하위 배열은 아직 범위 밖이다. PROVIDED_EMPTY를 미착용으로 해석하거나 NOT_PRESENT를 만들지 않는다 |
| 진단 근거의 값/가용성 타입 | 현재 evidencePath와 observedCount, category, ruleVersion이 있다. count가 null인 불리언 근거는 응답 경로로 확인 가능하다. 여러 값 타입을 다루는 진단을 추가할 때 명시적 타입을 설계하고 임의 Object 필드는 추가하지 않는다 |
| 스냅샷 비교 | 저장 범위 확정 후 진행한다. 두 시점 변화량은 관측 차이이며 특정 장비 변경의 인과적 전투력 기여도로 표시하지 않는다 |
| 시세 기준 | 거래소 매물·최근 체결·수동 가격·정적 규칙, 시각·구간·출처를 구분해야 한다. 아직 시세 API를 구현하지 않았으므로 필드를 형식적으로 추가하지 않는다 |
| 랭킹/점수 메타데이터 | 모집단·표본 수·집계 시각·규칙 버전·비교 조건이 먼저 필요하다. 검색한 소수 캐릭터를 전체 유저 랭킹으로 표현하지 않는다 |

저장 기본 OFF 정책, 주요 원천 상태 보존과 진단 연결을 완료했다. [원천 상태 계약](character-observation.md)과 [운영 지표](backend-operations.md)를 함께 참고한다. 장기 이력 비교는 보관 범위 확인 후, 비용·추천은 가격 출처와 게임 규칙 검증 후 진행한다.
