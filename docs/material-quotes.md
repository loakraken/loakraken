# 재료 구매 견적

`POST /api/v1/markets/material-quotes`는 입력한 필요·보유 수량과 공식 거래소 묶음 가격으로 추가 구매 골드를 계산한다. 성공 응답은 `200 MATERIAL_QUOTE_SUCCESS`다. 계산은 저장하지 않는다.

## 범위와 근거

2026-10-04 확인한 [공식 거래소 가이드](https://lostark.game.onstove.com/GameGuide/Pages/거래소)는 일부 재료의 묶음 거래와 수량에 따른 구매 단가 변동을 설명한다. [공식 Markets 명세](https://developer-lostark.game.onstove.com/swagger-doc/endpoints/markets)의 `Id`, `BundleCount`, `CurrentMinPrice`, `RecentPrice`, `YDayAvgPrice`를 사용한다. 공개 명세를 확인했으며 이번 구현에서는 실제 인증 API를 호출하지 않았다.

견적은 선택한 묶음 가격이 필요한 모든 묶음에 동일하게 적용된다는 계산 가정이다. 공식 목록에는 해당 가격에서 구매 가능한 수량이 없어 실제 체결 총액이나 구매 가능 여부를 보장하지 않는다. 최근 거래·전일 평균 기준은 과거 가격을 사용한 비교 계산이다. 가격 기준은 자동으로 대체하지 않는다.

[공식 재련 가이드](https://lostark.game.onstove.com/GameGuide/Pages/재련)는 실패 시 재료 소모, 성공률 증가, 장인의 기운, 성장 지원과 영지 연구 효과를 설명한다. 단계별 전체 확률·재료표와 보정 조건을 검증하기 전이므로 이 API는 목표 강화 단계의 기대 비용을 계산하지 않는다. 필요 수량은 사용자가 입력한 고정 계획이다. 입력 수량을 기대 소모량으로 임의 해석하지 않는다.

## 요청

```json
{
  "priceBasis": "CURRENT_MIN_PRICE",
  "items": [
    {
      "itemId": 123,
      "requiredQuantity": 250,
      "ownedQuantity": 40,
      "search": {"categoryCode": 50000, "itemName": "검증 재료"}
    }
  ]
}
```

ID와 이름은 합성 예시다. 실제 검색 응답에서 고른 ID와 검색 조건을 전달한다. 클라이언트가 가격이나 묶음 크기를 직접 지정하지 않으며 서버가 조회한 값만 계산한다.

| 필드 | 규칙 |
|---|---|
| priceBasis | 필수. CURRENT_MIN_PRICE / RECENT_PRICE / YDAY_AVG_PRICE |
| items | 필수, 1~10개, null 항목 불가, 상품 ID 중복 불가 |
| itemId | 필수 정수, 1~9007199254740991. 브라우저 정수 안전 범위 내 서비스 입력 정책 |
| requiredQuantity / ownedQuantity | 둘 다 필수 정수, 0~999999999. 소수 수량은 절삭하지 않고 400 |
| search | 필수. [기존 검색 조건](market-prices.md)의 정규화·기본값·검증을 그대로 사용 |

수량 단위는 해당 거래소 상품의 개수다. 파편 주머니를 선택하면 주머니 개수이며 내부 파편 수량으로 자동 환산하지 않는다. `ownedQuantity`에는 그 계획에 실제 사용할 수 있는 동일 상품만 넣는다. 사용 가능 캐릭터·귀속 여부·인벤토리는 서버가 검증하지 않는다. 보유 재료의 기회비용은 계산하지 않는다.

각 항목은 현재 판매 목록(`ACTIVE_LISTING`)의 지정된 한 페이지에서 정확한 ID로 찾는다. 다른 페이지를 자동 탐색하거나 비슷한 이름으로 대체하지 않는다. 상품이 페이지에서 이동했다면 재검색 후 검색 조건을 갱신한다. `ITEM_NOT_IN_PAGE`는 상품 전체 미존재를 뜻하지 않는다.

JSON 정수 필드에 소수를 전달하거나 enum 대신 숫자 순번을 전달하면 400이다. 애플리케이션 JSON 역직렬화 설정에서 정수 절삭과 숫자 enum 변환을 차단하며 기존 외부 응답·캐시 계약도 전체 회귀 테스트로 확인한다.

## 계산 규칙 material-purchase-v1

1. 부족 수량 = `max(0, 필요 수량 - 보유 수량)`.
2. 부족 수량이 0이면 구매 비용은 0, 외부 가격 조회는 생략한다.
3. 구매 묶음 수 = `ceil(부족 수량 / BundleCount)`.
4. 구매 상품 수 = `구매 묶음 수 × BundleCount`.
5. 잔여 상품 수 = `구매 상품 수 - 부족 수량`.
6. 골드 비용 = `구매 묶음 수 × 선택한 묶음 가격`.

정수 나눗셈과 나머지로 묶음을 올림한다. 금액은 BigDecimal 곱셈·합산으로 계산하며 중간 반올림과 임의 정수 반올림을 하지 않는다. 전일 평균을 선택하면 소수 골드 견적이 나올 수 있다. 프론트 표시 반올림은 계산값과 구분해야 한다.

필요 250개, 보유 40개, 묶음 100개, 묶음당 10골드라면 부족 210개 → 구매 3묶음·300개 → 잔여 90개 → 30골드다. 보유량이 필요량 이상이면 잔여 **구매** 수량은 0이다. 기존 인벤토리 잔여량은 별도 필드로 제공하지 않는다.

## 응답과 미계산 처리

`data`는 `ruleVersion`, `priceBasis`, `source`, `calculatedAt`, `complete`, `knownCostGold`, `totalCostGold`, `items`를 제공한다. 항목에는 입력 수량·정규화 검색 조건·부족 수량·상태·상품 이름·묶음 크기·선택 가격·`observedAt`·`purchase`가 들어간다. 모든 필드는 null이어도 생략하지 않는다.

`purchase`가 있으면 `bundleQuantity`, `purchaseQuantity`, `surplusQuantity`, `costGold`를 제공한다.

| 항목 status | 의미 | purchase |
|---|---|---|
| PRICED | 유일한 ID와 양수 가격으로 계산 | 계산 결과 |
| COVERED_BY_INVENTORY | 필요 0 또는 보유량으로 충당. 상품·가격 조회 생략 | 모든 수량과 비용 0 |
| ITEM_NOT_IN_PAGE | 지정 페이지에 ID 없음 | null |
| AMBIGUOUS_ITEM | 같은 ID가 페이지에 여러 번 존재 | null |
| TRADE_RESTRICTED_ITEM | TradeRemainCount가 0을 포함해 제공됨. 재거래·페온 조건을 계산하지 않으므로 제외 | null |
| PRICE_UNAVAILABLE | 선택 가격이 null. 다른 가격으로 대체하지 않음 | null |
| ZERO_PRICE | 선택 가격이 0. 원천 0을 보존하되 무료 구매로 해석하지 않음 | null |

재거래 상품 제외는 이 서비스의 보수적 적용 범위이며 모든 해당 상품에 페온이 반드시 든다는 주장이 아니다. 보유량 충당 항목은 상품 존재나 거래 제한을 확인하지 않았으므로 이름·묶음·가격·관측 시각이 null이다. 미발견/중복 항목도 상품을 선택하지 않아 이름·묶음·가격이 null이며 조회한 페이지의 시각은 남긴다.

`complete=true`는 모든 항목의 계산 가능 여부다. 시장 재고 확보나 재련 완료를 뜻하지 않는다. 하나라도 미계산이면 `complete=false`, `totalCostGold=null`이며 `knownCostGold`에는 계산 가능한 항목만 합산한다. 전부 미계산일 때도 소계는 0이지만 총액은 null이다. 소계를 전체 견적으로 표시하면 안 된다.

판매자 수수료·보증금, 페온, 재련 자체의 골드·실링, 추가 재료와 이벤트 보정, 파편 주머니 내용물, 경매장 장비·장신구·보석 가격은 포함하지 않는다. 예상 손익·효율·DPS·추천 순위를 제공하지 않는다.

## 시각·호출·오류

- `calculatedAt`은 계산 완료 시각이다. 각 `observedAt`은 서버가 해당 가격 페이지를 읽은 시각이며 캐시 적중 시 유지한다. 거래 체결 시각이 아니다.
- 한 견적 내 같은 정규화 검색 조건은 한 번 읽는다. 서로 다른 페이지는 순차로 최대 10개 조회한다. 각 페이지의 관측 시각은 다를 수 있고 원자적인 시세 스냅샷은 아니다.
- 기존 가격 30초 캐시와 동일 요청 병합을 공유한다. 조회 도중 만료 경계를 넘더라도 이미 읽은 페이지는 해당 견적 안에서 재사용한다. 견적 자체를 저장·캐시하지 않는다.
- 보유량 충당은 외부 호출 0회, 나머지는 서로 다른 미캐시 페이지 수만큼 외부 호출한다. 캐릭터·옵션과 공유하는 90회/분·동시 4개 예산을 사용한다. 자동 재시도나 전체 페이지 순회는 없다.
- 입력 검증 실패는 조회 전에 `400 INVALID_REQUEST`, JSON 이외 본문은 `415 UNSUPPORTED_MEDIA_TYPE`다.
- 기존 429/502/503/504를 그대로 반환한다. 외부·캐시 장애를 미계산 항목으로 숨겨 200으로 바꾸지 않으며, 오류 이후 페이지도 조회하지 않는다. 오류 이전에 읽은 페이지의 단기 캐시는 남을 수 있다.

## 검증

순수 계산 테스트는 묶음 경계·정수 상한·정확한 소수 곱셈을, 서비스 테스트는 세 가격 기준·보유량 충당·미계산 사유·같은 페이지 재사용·실패 전파를 확인한다. 실제 HTTP/Valkey 통합 테스트는 기존 검색 캐시 재사용, 수량 절삭 방지, 중복 항목·잘못된 JSON·중첩 입력 검증, nullable 응답을 확인한다. Swagger 요청/응답 계약과 `material-quote.json`, `material-quote-incomplete.json` 합성 산출물을 검증한다.
